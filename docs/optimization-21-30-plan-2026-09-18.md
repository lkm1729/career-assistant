## O7：网页入口与间距（21、22）

- 拉开网页输入、用途设置、“读取网页前确认”按钮之间的距离；窄窗口采用纵向排列，兼顾浅色、深色和键盘焦点。
- 简历评分开放多链接输入，逐条设置个人项目/补充证据、目标岗位等现有用途；读取前确认实际链接与用途。
- 复用资料多选/全选删除，明确选中数量与范围；参与 AI 发送的勾选独立于删除勾选。
- 目标岗位与个人项目不得混用，多岗位仍需现有确认；网页抓取失败不影响同批成功项。

验收：多链接混合用途、修改用途后重启、跨页隔离、未确认不读取、未选资料不发送、取消删除、窄屏无重叠。

## O8：评分完整性修正（26）

先建立能稳定重现过严拦截的测试，区分三层：原文件完整、本机解析/渲染完整、实际发送且模型覆盖完整。用户上传完整文件不等于后两层必然完整。

- 总分门槛围绕本次选中的简历及所需维度，不因无关未选资料而失效。
- 将阻断原因分开显示：未发送图像、解析缺页、页面不可读、模型遗漏覆盖、维度未完成、影响评价的冲突。避免一个笼统提示掩盖原因。
- 核对图像开关、模型能力、页别名映射、覆盖清单提示与解析路径；区分轻微质量提示和确实无法评价的情况。
- 对缺漏字段只能采用可验证的格式规范化；不根据“文件看起来完整”伪造模型覆盖，也不自动补分、填零或调整权重。
- 无图像时不得生成视觉分数；真正不可读、漏页或证据不合法时继续提供明确的部分评价。
- 不自动重试付费请求，不增加隐式上传。若需真实供应商复现，另行确认材料和调用范围。

验收：完整单页/多页图像、有未选补充资料、纯文本、图像关闭、渲染缺页、低清但可读/不可读、模型漏报、冲突及非法证据；正常完整结果可计算总分，真正缺失仍被阻断。实测原因未确认前不声称全面修复。

## O9：结果区视觉层级、按钮与引用展示（23、24、24.5）

- 四页结果区使用统一的 AI 回答标识、突出标题、边框/底色层级与适度阴影；区分生成中、已完成、历史结果及手动编辑。
- 可以提供“查看 AI 结果”的定位入口，避免流式输出强制抢走滚动位置或编辑焦点。
- 主操作、次操作、危险操作按钮统一样式；先核对已改样式，仅补齐不一致部分。
- 动效只用于真实状态；遵守减少动态效果偏好，避免持续闪烁和逐 token 昂贵重绘。
- 引用默认显示资料名称、页码与引用原文；UUID、sourceId 和调试 JSON 收入可展开详情，不从内部存储或校验中删除。
- 默认使用清晰的 Markdown/段落/列表，不把 JSON 作为普通用户阅读评价的默认形式。已有记录没有来源名称时显示“参考资料 / 第 N 页”等诚实降级文案，不猜名称。
- 保持 Markdown 安全渲染，不为美化放开任意 HTML。

验收：四页长结果、长引用、多条来源、旧历史、浅深色、窄屏、减少动态效果；引用仍可追溯，未选资料名称不泄露。

## O10：历史与草稿批量管理（25、27）

- 回收站、切换前草稿、评分历史、匹配历史各自增加多选/全选/取消选择和批量删除。
- “全选”明确当前列表范围和总数；若跨分页，应显示跨页选中数量，不让用户误认为只删除可见项。
- 当前工作区草稿、切换前草稿、正式版本、评分/匹配历史分别处理，不能用一个清空操作混淆含义。
- 确认界面说明数量、范围、是否可恢复；永久删除使用明确危险操作，并由用户在应用内最终确认。开发测试只使用隔离测试数据。
- 删除不串页、不删除原始文件、不连带删除输入资料和供应商配置。
- 若被删记录当前正在查看，退出到空态或仍存在的记录，不显示已删除的“幽灵记录”；删除历史不应顺带清空独立保存的当前正文。
- 运行中的关联数据修改需受保护；服务端校验归属，处理重复 ID、失效 ID、取消及失败，避免前端显示与持久化不一致。

验收：空列表、单选、多选、跨页全选、取消、失败、刷新/重启、删除当前查看项、运行中保护、跨页隔离和旧数据兼容。

## O11：确认页降噪与运行信息（28、29、30）

- 四页确认窗口首屏只保留本次操作、将发送的资料/图像数量、供应商/模型、必要隐私/费用提醒和确认/取消。
- 端点、参数 JSON、格式约束解释与诊断项移入可展开详情；不删除实际发送预览和必要授权信息。
- 用普通语言替换不必要术语；将“文字精简”和“性能优化”分别验收，只有测量证明后者才声称减轻卡顿。
- 评分和匹配总览卡片右下显示评估时间、当次供应商及模型。时间取历史记录的 createdAt 并标明本地时间，不使用查看时刻；如需精确开始/完成时间，另定义字段，不曲解现有时间戳。
- 四页触发按钮旁显示下一次将使用的供应商、模型和接口协议，遵守本页配置覆盖规则。未配置时显示明确状态。
- 运行中显示本次连接快照；完成结果显示历史快照，避免切换设置后把旧结果标成新模型。

验收：切换供应商/模型/协议、本页覆盖、未配置、长模型名、历史回看、重启后快照一致、窄屏、展开详情与取消确认。

## 顺序与交付

建议 O7 → O8 → O9 → O10 → O11。O8 可在 O7 前建立诊断基线，O7 完成后回归新增网页资料对评分的影响。O11 复用 O9 的视觉规范。
每一批分别报告类型/服务测试、桌面 E2E、截图、持久化与最终包 smoke 的实际结果。模拟供应商不等于真实供应商验证；本机打包不等于独立干净机器验收。
本方案不授权永久删除真实历史、不扩大到重构全应用，也不将先前发布的签名/许可证等验收事项视为已解决。
