# 0.7.2：剩余测试建议补齐

日期：2026-09-15。基于用户已验收的 0.7.1，保留旧版目录，不执行 commit/push，不使用真实 Key 或付费 API。

## 实际交付范围

### 1. 切换和回滚沿用原版本，不新增编号

- 简历和求职信都可以通过“切换工作版本”下拉框或历史记录的“切换到 Vn 并编辑”进入该版本的真实编辑区。
- V3 切回 V1 后仍为 V1，不自动创建 V4。手动修改显示“编辑稿 · 基于 V1”，不会改写已保存版本。
- “回滚到 Vn”有确认步骤，替换当前正文并清空待处理修改要求；保留当前基础资料、系统提示词和模型配置。
- 回滚/切换前的完整草稿保存到“切换前草稿”；可选择任意备份并确认恢复。恢复备份前也保留当前草稿。
- 再次成功生成或 AI 调整才产生新版本，例如在 V1 基础上生成 V4；原 V1/V2/V3 继续保留。
- 旧版曾经生成的 restore 记录不重写或删除，仍作为历史正文版本保留。

### 2. 旧版本多选删除与撤销

- 历史列表支持单选复选框、全选和批量删除确认。
- 当前工作版本不可删除，整批包含当前版本、过期引用或重复项时拒绝整批操作。
- 删除是可撤销的“移入回收站”，不覆盖工作区、不重排编号、不物理擦除正文数据。
- 回收站可多选恢复，恢复沿用原编号，不自动切换工作区。回收站和草稿备份在重开后保留。
- 简历、求职信的数据完全按页隔离，不能通过另一个页面的编号恢复或删除内容。

### 3. 供应商连通性探针

- 在所选供应商下可直接测试，不需要先添加模型。
- 显示最终 GET 模型列表地址、协议和发送说明，明确确认后才使用已保存 Key 发请求。
- 按 Chat/Responses、Gemini、Anthropic 分别使用其认证请求头，不跟随重定向；15 秒超时、响应体上限 1 MB、可取消。
- 结果写入供应商配置，修改供应商后旧测试标为过期。
- 列表探针通过不保证模型可生成；代理可能不支持列表，探针失败不会阻止继续单独测试模型。模型文本/图片探针继续保留。

### 4. 红色结构化错误诊断

- 供应商探针、模型探针、模型/供应商配置错误，以及生成/版本操作失败，都能展示红色诊断信息。
- HTTP 状态通过 `AI_HTTP_401` 等应用错误码和 HTTP 数字保留；网络、超时、流/格式、配置变化、本地存储等另有应用错误码。
- 展示“可能原因（并非已确认）”和建议办法；不把猜测当作供应商的事实结论。
- 不显示服务商原始错误正文或网络异常细节，避免回显 Key、请求内容或内部信息；不自动重试付费生成。

### 5. 求职信纯文字链路与加载反馈

- 为让求职信的版本管理可实际使用，接通本页纯文字生成、调整、确认、取消、流式状态和独立版本库。
- 求职信只读取本页资料、提示词、当前正文及修改要求，使用本页选择的供应商/模型，不读取简历页正文或暂存网页链接。
- 求职信格式约束明确要求求职信正文，不套用简历正文约束。建议与说明分别保存。
- 简历/求职信运行中使用旋转图标和渐变文字，锁定正在生成的页面；供应商/模型探针同样有运行提示。系统减少动态效果选项可关闭动画。

## 未扩张的阶段

P08 继续暂停：不读取用户附件、图片或网页。评分和岗位匹配 AI 尚未接通，不增加假进度或演示分数。求职信只提前完成文字子集，不宣称完整 P11 或完整多模态验收已完成。

## 数据安全与兼容

- 增加 letter_versions、deleted_document_versions、document_checkpoints 表；不重建或清空原数据库。
- 版本切换、草稿恢复和删除/撤销使用本地事务；草稿发生并发修改或确认已过期时拒绝覆盖。
- 版本正文不可变；删除为标记，原编号不重复使用，已删除的运行 ID 仍阻止重复生成。
- 保留原密钥加密存储，探针仅在主进程使用密钥；正文和备份仍是原本未加密的本地 SQLite 数据，须自行保护本机用户目录。
- 不建议降级编辑同一份数据库：旧版不认识回收站标记，会重新显示已删除版本。旧 EXE 文件原样保留。
