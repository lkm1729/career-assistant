## 边界

多岗位检查是对多个输入来源的保守提示，由用户确认不是自动语义判定。静态快照和现有 CityU 公开数据适配之外的动态/登录站点使用手动替代路径，不承诺所有站点可抓取。提示注入测试验证资料与指令的程序边界，不是模型安全性的形式化证明。

P14 安装器、字体/依赖许可证、签名和干净电脑验收不在本轮。ZIP 测试版交付不关闭 P14。用户已验证的 Claude/Gemini 场景与本轮模拟矩阵分别记录，不泛化为所有供应商均已实测。

## 本轮修复的回归与交付缺口

1. 未勾选资料的文件名原来出现在会发给模型的 warnings。用虚构名称回放 0.10.6 源码得到红测试（`.test-data/0.11.0-omission-red.txt`），当前实现只发送数量，绿测试及四协议四页服务矩阵通过。继续使用“未选中：”警告前缀以保持旧评分遗漏资料时不能计算完整总分的保守规则。
2. 本轮给附件组件添加的 key 与同级参数/提示词组件重复，首轮完整桌面回归捕获到重复附件控件/勾选失败。并非网页或供应商错误，也不是仅测试选择器问题。新的 `unique attachment` 桌面回归在候选包上确实失败（期望1，实得4），修正为各组件独立命名 key 后重新构建与验收。被拒绝的候选包已可逆移到 `.test-data/0.11.0-rejected-package`，不作为最终发行物。

## 测试运行环境说明

首次沙箱内 Electron 图形子进程启动崩溃，桌面用例超时；没有通过禁用 Electron 沙盒或证书验证规避，而是在获批后用相同安全配置进行沙箱外隔离测试。全部业务测试仍是虚构资料/本机模拟端点。真实 CityU 网页测试需明确 opt-in，本轮禁用并标为跳过，不自动进行外网验收。

首次完整回归发现 P05 旧桌面测试断言过时文案，先改为核对 `AI_STREAM_INCOMPLETE`。中断恢复后的完整回归进一步证实：显式 incomplete 事件已提供该错误码，但缺失 response.completed / 完整完成事件的旧错误文案仍被通用分类器映射成 AI_RESPONSE_FORMAT。独立重跑稳定复现后，在 shared/diagnostics.ts 补齐这两种完成事件缺失的分类，新增两项单元回归；桌面失败用例重跑通过。不放宽流完成条件、不自动重试、不保存失败结果。
