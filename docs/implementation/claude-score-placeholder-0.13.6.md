# Claude评分数字引用与误置空示例 · 0.13.6

日期：2026-09-19。基线0.13.5。用户提交一份新的单行响应和另一条“dimensions须包含四个且仅四个维度”报错。只读使用已授权附件，不读取正式数据库或系统剪贴板，不调用真实供应商。

## 重现与真实根因

1. 新附件6416字符、3行（围栏+单行JSON），旧parseScore稳定重现AI_SCORE_JSON / SEPARATOR_REQUIRED。
2. 首轮普通语法失败于正文裸引号；旧兼容语法继续至一条问题说明中的四位数字引用。原规则统一拒绝纯数字引用，把紧贴中文正文的年份也当成潜在缺逗号的数值。
3. 单变量实验：仅将该数字引用的两个已有引号转义，旧解码器即能读取全文。没有补字段/逗号/引号或改写文本。
4. 解析后发现dimensions实际有5项：四个规定维度各一次，另有且仅有一个精确对象 {"key":"example","value":null}。此空示例占位误放进维度数组，能触发与用户另一条报告相同的AI_SCORE_DIMENSIONS。不能据此断定未提供原文的另一条报错也必然相同。
5. 虚构最小回归分别锁定数字引用、五项数组、以及二者组合。修复前红灯日志red.log，修复后green.log。

## 修复与边界

- 在已经允许的说明字段中，仅接受数字引号内没有额外空白、且开/闭引号外侧紧贴文字字母的明确正文引用。仍拒绝独立数值、缺逗号样式、真假/null原子、截断、跨结构边界及含糊引号；正常JSON始终优先。
- 新增score-dimensions.ts：仅当数组恰好5项，四个正式维度完整且唯一，额外对象严格只有key/example与value/null这两个属性时，排除该空占位。添加EMPTY_EXAMPLE_PLACEHOLDER提示。四个正式维度对象原样保留，后续分数、证据、来源、图像覆盖和完整性继续全部校验。
- 不接受6项、多占位、带非空value或score/evidence等其他属性的example，不删除真正额外评分，不补缺失维度、不合并重复维度。未知字段名/内容不进入诊断。
- 维度错误增加shape、count、missing、duplicate、unknownOrInvalid。只使用本地固定key词汇与数量，不输出供应商自定义key或文本。
- 评分提示词强调四项唯一、资料不足仍保留score:null对象；example是维度对象内属性，不能变成第五个对象。
- 自愿的单次失败响应预览增加AI_SCORE_DIMENSIONS范围，确认标签与解释同步更新。默认关闭、按次同意、已知Key遮蔽、5分钟内存缓存、二次查看/复制确认、关闭/切页/新运行清除等行为保留。证据错误、HTTP错误、流中断仍不捕获，不自动付费重试。
