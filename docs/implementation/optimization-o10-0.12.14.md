## 本轮实现与数据边界

### 四种独立列表

- **简历/求职信回收站**：多选、全选全部分页、取消选择、恢复所选版本，以及单独的“永久删除所选回收站版本”。原有“正文版本→移入回收站”继续可恢复，不能与永久删除混淆。
- **简历/求职信切换前草稿备份**：新增多选、全选、取消选择和永久删除。这里是切换/回滚/清空前的备份，不是当前工作区草稿；现有恢复功能保留。
- **简历评分独立评估历史**：单独批量管理。
- **岗位匹配独立匹配历史**：单独批量管理，不与评分混用。

每种列表每页展示20条，明确显示“全选本页全部…（共N条，含全部分页）”和“已选N/M”。跨分页勾选保留，取消选择明确可见。删除依据确认时选中的具体标识集合，不使用确认后重新扩大范围的“删除全部”命令。501条数据的全选删除由一个事务完成，不按500条分成可能部分成功的多个提交。

### 删除安全

- 两步操作：选择并点击永久删除后，显示数量、当前标签页/列表范围、跨分页范围、不可恢复性和不会影响的数据；用户在应用内最终确认才执行。
- 选择变化使确认失效；评分/匹配的当前显示修订变化也使旧确认无效。主进程再次验证运行空闲、工作区归属、重复/失效ID及版本身份。
- 版本核对使用本页编号与runId共同匹配，只允许永久删除回收站记录；当前工作版本不可永久删除。
- 批量删除全程SQLite事务：任一目标缺失、属于另一页、重复或数据库中途失败，整批回滚，不先删除一部分。
- 若删除正在查看的评分/匹配记录，明确退出到空态，重启后不会自动复活旧记录。其余历史可另行选择恢复显示。
- 若删除的是“恢复刚清空结果”的目标记录，相应即时撤销失效；未删除的撤销目标仍可用。界面与持久化状态同步。
- 永久删除正文版本后，独立保留的草稿备份/即时撤销文字不会被连带清空；如恢复它们，已不存在的工作版本指针降级为本地草稿，不产生幽灵版本。
- 不删除当前输入正文、资料项、原始文件、其他标签页历史、提示词副本或供应商/模型设置。不上传资料，不新增真实API请求。
- **永久删除不是安全擦除**：仅移除所选记录；其他独立备份/版本可能仍含相同文字，SQLite文件也不保证立即缩小。本轮不对真实库做VACUUM、迁移清理或文件夹清空。
