# 0.10.6 · 岗位匹配请求编排修正

日期：2026-09-16。基线 0.10.5。用户授权实施兼容性修正并交付新版 Windows 项目。本轮未获授权调用真实 API，因此不读取密钥、不上传真实资料、不发起付费探针。

## 问题与修复边界

用户确认 Claude 的列表/文本/图片探针可运行，但岗位匹配生成 Markdown 并被 AI_MATCH_MARKDOWN 拒绝。此前调查未找到能够证明真实故障根因的响应捕获；不能把网关或用户自定义提示词当成已确认原因。

本版修正已知的请求表达弱点：原来用户消息是原始输入/材料集合，完整输出要求仅在 system。不是声称旧请求违反 API 规范，也不是声称只靠提示词即可强制所有模型遵从。

## 实施

1. shared/matching.ts 增加两段固定、非私密、长度有测试上限的业务指令：明确任务与资料读取规则；材料结束后重申 JSON 字段、枚举、原文引用和缺失信息的表达方式。
2. electron/match-request.ts 集中构造匹配消息。顺序为：原系统消息和既有 JSON 契约；用户任务指令；原始输入/来源清单；每页材料与对应图片；最终固定输出要求。正文各发送一次，不复制整份简历/岗位来增强提示。
3. 显式说明 job/resume/evidence 为空只表示未粘贴文字，仍应读取 purpose=resume 等已选资料。资料、文件名和网页均作为数据，不是改变输出格式的指令。图像仍紧随对应页面文字，最后一部分固定为输出要求。
4. AiService 仅使用主进程重新计算、验证后的 current 构造消息，保留旧确认失效、跨页隔离、取消、幂等和失败不保存。
5. 不改变 Chat / Anthropic JSON Schema 的启用条件与字段；Gemini/Responses 不新增供应商格式参数。四协议共用更明确的业务消息，不按模型名称或供应商写特殊分支。
6. 发送确认框展开可看系统输出契约、材料前任务与材料后输出要求，使用同一组常量避免 UI/请求漂移。固定指令计入输入 Token，界面说明不增加请求次数、也不保证模型必然遵从。
7. JSON/来源/连续原文/硬性条件校验原样保留。没有自动重试、自动降级、Markdown 猜测转换或二次模型“修复”。用户配置、系统提示词、正式数据库与既有版本/记录不改。
