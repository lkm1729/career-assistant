# O4 — 清空当前工作台成果 / 0.12.8

日期：2026-09-18。基线：0.12.7.2。用户已表示上一轮问题大致解决，并明确进入清空工作台功能；章程编号为 O4（用户称 Q4）。仅实现第 15 项，不进入 O5 / O6。

## 功能与范围

四页在输入区与成果区之间新增“清空当前结果”，反馈紧邻按钮。

- **设计简历 / 撰写求职信**：清空当前正文（含手动编辑），解除当前正式版本选择，旧建议和说明不再作为当前建议展示。确认框明确说明手动正文也会清空。
- **简历评分 / 岗位匹配**：只清空当前显示的评估，不删除评估历史，也不清空输入的简历文字。
- **保留**：输入要求、修改要求、提示词、网页草稿、文件/图片/网页资料及选择状态、模型/供应商设置、全部历史、其他页面。
- **即时恢复**：“恢复刚清空的结果”恢复正文/原工作版本或原评估选择，不倒退清空后编辑的新输入。
- **长期恢复**：写作页清空前保存完整“切换前草稿”，沿用本页记录中已有的明确确认恢复入口；该入口会恢复当时完整输入，界面继续明确告知此范围。正式版本可直接切换恢复。
- **评估历史恢复**：选择旧评估即恢复显示，并持久保存选择。匹配页原本的历史列表位于当前结果分支内，清空后将无法访问；现独立放置，并接通“本页记录”的匹配历史入口。
- **持久化**：清空后重启维持空白，不自动选回最后一条评估；再次成功生成/评估后正常显示新成果。
- **有限撤销**：新正文编辑、正式版本切换、新生成/新评估、选择旧评估均使即时撤销失效，避免覆盖新成果；原有历史/写作草稿备份仍保留。
- **不是永久删除**：不会压缩数据库、擦除历史、删除附件或释放原始文件空间。未增加“删除全部历史”。

## 存储与一致性

新增 `workbench_results(page,payload)`，按页面保存当前评估选择、状态 revision 与即时恢复信息。所有字段只留本机 SQLite，无供应商请求。

- 旧数据库没有状态行时继续显示其最新评估，保持升级前行为；显式保存的 `currentId=null` 表示已清空，不使用 `?? 最新记录` 回填。
- 清空前比较确认时的状态 revision 与完整持久化草稿；确认后输入/成果发生变化时拒绝执行。
- 写作页“备份 → 清空正文 → 写状态”处于同一个 SQLite 事务。
- 评估“写入新记录 → 更新当前选择”处于同一个事务；故障注入确认写入失败会回滚，不产生记录已成功而选择未更新的半状态。
- 普通写作编辑、历史切换/恢复、AI 正式版本保存同步废弃旧即时撤销；不更改历史版本编号。
- 原工作版本若清空后被移入回收站，即时恢复要求先恢复该版本，不绕过回收站标记。
- Renderer 冲刷 WriteQueue 后再准备清空快照，操作期间锁住输入；主进程单独验证，不能只靠禁用按钮。
- 生成/评分/匹配运行中禁止清空和恢复选择。等待取消真正结束之后才可操作。
- 评分/匹配发送确认包含结果状态 revision；清空、撤销或选择结果之后旧确认不可继续发送。写作 UI 同样携带该 revision，防止清空再撤销后误用旧确认。
- 文件导入进行时，主进程拒绝成果变更。

## 主要代码

- `electron/workbench-store.ts`：结果状态、事务、校验、清空/恢复/选择。
- `electron/workspace-store.ts` / `document-history.ts` / `ai-store.ts`：写作编辑、历史与生成的一致性。
- `electron/scoring.ts` / `matching.ts`：评估成功与当前选择原子写入。
- `electron/ai-service.ts` / `main.ts` / `preload.ts`：运行互斥、旧确认失效及 IPC。
- `shared/workbench.ts`：类型化本地接口。
- `src/ClearResultControl.tsx`：范围确认、撤销和就近反馈。
- `src/useScore.ts` / `useMatch.ts`：从持久选择初始化，失败/清空不回填最新记录。
- `src/MatchPanel.tsx` / `controls.tsx`：空工作台也能访问匹配历史。
