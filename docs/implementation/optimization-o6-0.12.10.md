# O6 — 性能诊断与优化 / 0.12.10

日期：2026-09-18。用户已验收 O5 / 0.12.9 并授权进入 O6。本轮不调用真实供应商、不读取正式 AppData、不清理旧版本、不提交/推送。

## 可复现性能环路

- 测试：`tests/o6-performance.e2e.ts`，夹具 `tests/o6-performance-fixture.ts`。
- 命令：`node node_modules/@playwright/test/cli.js test tests/o6-performance.e2e.ts --output=.test-data/o6-<run>`。
- 同机 AMD Ryzen 7 5800X，同 Electron/依赖、生产构建模式、1440×1000 测试窗口。基线使用保留的 0.12.9 ASAR（`CAREER_E2E_APP_PATH`）；优化使用本地构建，后续再验证最终 ASAR。
- 小数据：2 个供应商/9 个模型，每页 2 项未选择的虚构资料、5 个 Markdown 小节。
- 大数据：2 个供应商/500 个模型，每供应商 250 个；每页 16 项未选择的虚构资料（每项约 2–3 KB），300 个 Markdown 小节。评分页使用隔离 TXT 文件，其他三页使用本地补充资料；导入必须成功且数量/默认未选择状态有断言。确认不发出请求，不包含未选择资料；所选资料快照另外用功能回归校验。
- 设置开关、模型编辑、四页确认各 3 次；快速切换供应商 12 次。长任务以 localhost SSE 每 10 ms 提供一段虚构文本，在 2.4 秒采样窗口中打开设置，最后显式取消，不保存不完整结果、不自动重试。
- 指标：操作至 DOM 断言及两个动画帧的时长（含自动化调度成本，不冒充真实用户 INP）、rAF 帧间隔、PerformanceObserver Long Task、DOM 元素数、React 根提交计数。测试专用 hook 只计数，不遍历/保存 fiber、正文或凭证。没有生产日志或遥测。
- 中位数及 p95 由 `node scripts/o6-performance-report.mjs <输出目录...>` 计算；每操作仅 3 次的 p95 实际是最大值，不代表大样本统计置信度。
- 回归门槛：每场景中位最大长任务 <100 ms；大数据写作页确认操作中位 <230 ms。`CAREER_PERF_CAPTURE=1` 仅用于明确的采集模式，不用于最终验收。

## 基线与逐项验证

初始 sandbox 启动 GPU 子进程失败，记录在 `.test-data/o6-baseline-a`；升级权限后可运行。隐藏窗口 rAF 约 1 Hz，`.test-data/o6-baseline-b` 的交互/帧数据无效，因此改用 `showInactive` 测试窗口。正式基线 `.test-data/o6-baseline-final` 复现失败：大数据设置开启最大长任务中位 164 ms（另外可见窗口一轮 155 ms），不是借用隐藏窗口的失真值。

按顺序验证的假设：

1. 一次挂载大量模型卡片导致主要长任务。只做分页后（`.test-data/o6-paging-only`），大目录切换约 65–73 ms，DOM 9247 → 3178，确认耗时仍约 230 ms，支持此判断。
2. 不变正文的 Markdown 被根状态变动重复解析。仅对该渲染节点按精确正文文本做 `useMemo` 后（`.test-data/o6-memo`），写作页确认进一步下降。编辑、版本变化、清空/恢复会自然失效；不是缓存生成输入或发送清单。
3. 目录 filter 重复计算尚未显示为独立主要瓶颈，因此没有全面 memo 或额外目录索引。
4. 流式更新已有 80 ms 合并。根提交次数大致相同（大场景采样均 33 次），单次工作变少即可消除采样中的长任务，因此不降低更新频率或大改 context。

大数据阶段性比较（毫秒，基线 → 分页+Markdown缓存）：

| 操作 | p50 | p95 | 帧间隔 p95 | 长任务次数 |
|---|---|---|---|---|
| 打开设置 | 293 → 94 | 294 → 144 | 170 → 54 | 3 → 0 |
| 切换供应商 | 252 → 71 | 342 → 73 | 97 → 42 | 19 → 0 |
| 返回模型列表 | 174 → 62 | 186 → 62 | 121 → 42 | 6 → 0 |
| 设计简历确认 | 272 → 192 | 288 → 204 | 73 → 49 | 0 → 0 |
| 求职信确认 | 269 → 183 | 269 → 234 | 67 → 49 | 0 → 0 |

长任务+打开设置阶段包含固定 2.4 秒等待，不能将其总时长作为“操作响应时间”；该阶段最长帧间隔 145 → 48 ms，长任务 3 → 0。简历评分/岗位匹配确认未证实有相同 Markdown 瓶颈，不宣称已专门优化其服务端准备时间。小数据输入/切换指标相近，不夸大收益；本机采样不是全硬件、固定 60 FPS 或供应商响应时间保证。

## 实现与兼容边界

- `src/RegistrySettings.tsx` + `src/ListPager.tsx`：每页最多 25 张已配置模型卡片，搜索覆盖本供应商全部名称/ID；分页不改变全选/删除集合。切换供应商不混用其搜索/模型；翻页/搜索取消尚未提交的测试/删除确认；运行时保持原有锁定。
- `src/panels.tsx`：精确正文依赖的渲染缓存。保留 skipHtml、惰性链接与不加载外部图片，复制/导出仍读取同一正文树。
- 不修改 MaterialManifest、协议解析、AI_TIMEOUT、JSON校验、发送快照、O4 数据表、O5 列表获取/导入服务或隐私边界。
- 编辑前原文件备份：`.test-data/o6-source-before`。

以修正后的夹具、同一计数器和同一开发 Electron 串行加载保留的 0.12.9 ASAR / 最终 0.12.10 ASAR。产物已构建完成后测试；输出 `.test-data/o6-comparison-before` / `.test-data/o6-comparison-after`。旧版大数据按预期红（设置长任务中位 158 ms），新版 2 项全部绿。只读观察流预览节点的 MutationObserver 仅记录更新次数；未读取或保存流文本。
