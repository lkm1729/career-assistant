# 0.10.1 · CityU岗位读取与匹配流式响应修复

日期：2026-09-16。基线0.10.0，旧包完整保留。

## 两个问题的确认范围

### 1. 用户提供的CityU/Kinobi岗位链接：已复现读取器缺陷

- 原页面HTTP成功但初始HTML只有CITYU标题，旧文字抽取器得到5字符，触发“网页可用文字过少或超过120000字符”；这是应用的网页读取阶段，不是模型失败。
- 查阅该页面公开脚本后确认，未登录页面使用固定公开岗位接口 `/api/job/{slug}/public`。实现仅针对 `cityu.app.kinobi.asia` 的显式适配，目标固定为 `cityu.server.kinobi.asia`；绝不从不可信HTML提取可执行代码或任意API地址。
- 实际读取约4326字符，包含职位标题、公司、职责、要求等。保留网站原文中的提示；站点要求用户参考岗位正文的提醒不会被移除或当作应用系统指令执行。
- 岗位职责/要求既支持字符串，也支持该站实际使用的 `{text: string}[]` 数据结构。只映射公开岗位必要字段，不复制联系人列表、邮件收件人、申请人数或后台配置。格式变化、slug不一致或缺少有效正文时拒绝导入。
- 访问前确认窗口显示公开数据接口；原网页地址仍保留为资料来源。无Cookie、登录、网页脚本、模型Key或简历外发。新快照默认不勾选，仍需第二次确认才发送给模型。
- 公共IP验证、DNS钉住、TLS校验、时间/大小上限继续保留；专用接口不跟随重定向，不退到登录接口。其他动态站点不冒充已支持。
- 空网页、过长网页、网络、超时、取消分别使用WEB_CONTENT_EMPTY、WEB_CONTENT_TOO_LARGE、WEB_NETWORK、WEB_TIMEOUT、WEB_CANCELLED，不再把它们描述为模型配置/供应商计费问题。

### 2. “响应未完整结束或达到模型输出限制”：部分可复现缺陷已修，真实供应商根因未确认

用户给出OpenAI Chat Completions、Gemini原生、Anthropic Messages，以及模型显示名Gemini-3.8-Flash、Claude-Sonne-5。未读取真实密钥/简历或调用真实供应商，因此不能断言用户每次报错的唯一根因。

已确认的代码问题：

- 匹配请求在`sources`和附件正文里重复发送PDF抽取文字。本版`sources`只传来源元数据，正文只发送一次；历史仍保留完整输入快照。
- Chat Completions旧版把缺少DONE、缺少stop、空正文、达到length限制混成同一错误。本版按已确认的协议事实分类：AI_OUTPUT_LIMIT、AI_STREAM_INCOMPLETE、AI_EMPTY_OUTPUT、AI_UNSUPPORTED_COMPLETION。
- 兼容完整分帧的`finish_reason=stop`后正常EOF但省略DONE的流；LF/CRLF/CR及分片边界均测试。仅最终DONE哨兵可省略最后空行，不推断未完整分帧JSON事件；缺少正常stop、真正截断、length、工具/拒绝状态仍不可保存。业务JSON和证据校验继续执行。
- Gemini MAX_TOKENS、Anthropic max_tokens和Responses明确的max_output_tokens标记统一报AI_OUTPUT_LIMIT。Responses未给出截断原因时仍报流不完整，绝不猜测是token上限。
- 匹配输出提示要求短引用、短说明并合并重复要求，不省略硬性条件；不回显整份资料，不输出推理过程。
- 确认窗口提示本次实际输出预算（包括“未指定，使用供应商默认值”）。没有偷偷提高参数、自动续写、自动重试计费请求或把推理文字当正文保存。

后续定位：请用户使用本版再测，提供新错误码、实际协议、模型ID及本页输出上限即可；不要提交API Key、Cookie、简历或未经脱敏的完整供应商响应。
