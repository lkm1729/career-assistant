## 修复边界

1. 正常JSON解析始终优先。有限兼容中，仅将已处于引文内的配对[文字占位词]视为字符串文字；追踪已转义与裸引号混合，避免把已有合法引文中的括号当作结构。占位必须含文字、限定字符、长度不超过160，不接受引号/逗号/冒号/换行/嵌套结构。实际数组如[1]、[true]、["x"]及对象仍拒绝。
2. 允许dimensions[i].evidence[j].quote采用同一明确成对引号规则。只解码已有字符，不改变摘录正文；之后仍走既有sourceId、实际来源与连续原文/图像证据校验。不将quote等同sourceId，后者和key、score、页面ID等仍严格解析。
3. 误置空示例只识别两个精确形态：key:example + value:null，或key:example + example:null。仍要求恰好5项且四个正式维度完整唯一；对象有额外字段、同时含两种属性、非空示例、额外评分、多个占位、缺维度/重复维度均拒绝。只排除不含内容的明确空占位，保留原四维并显示提示。
4. 评分输出指令补充证据quote引号也必须逐字JSON转义，建议占位属于字符串而非数组或字段。无需改变供应商协议/模型能力，不自动收费重试。
5. 保留700000字符、64层嵌套、16000字符说明值、32对内引号边界；不跨第一个结构分隔符找“方便的结尾”，不修补缺失字段、引号或分隔符。诊断入口及其默认关闭/按次同意/5分钟内存与清理机制本轮不变。
