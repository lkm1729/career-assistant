# P05：OpenAI Responses 接入

日期：2026-09-15
版本：0.5.1（0.5.0 的 P05 功能及本地优先加固）

## 交付范围

- 供应商默认协议新增 OpenAI Responses；模型可继承或显式选择 Chat Completions / Responses。
- 两个协议使用独立请求与流事件适配器，共用简历生成、调整、取消和事务性版本保存。
- Responses 可完成 V1 生成、V2 调整、旧版只读预览、恢复新版本、关闭重开；历史保存当时的协议和模型快照。
- 文本与图片样本测试均走所选模型的真实协议；分别确认、分别留测试记录，不以文本通过冒充视觉已验证。
- 修改供应商或模型协议使旧能力测试记录过期，不改写旧版本。
- 本次不启用 Gemini、Anthropic，不提前实现文件导入、评分、岗位匹配或求职信生成。

## 官方协议依据

于 2026-09-15 直接读取下列 OpenAI 官方页面（HTTP 200）。实现不依赖第三方教程：

- Streaming responses：`https://developers.openai.com/api/docs/guides/streaming-responses`
- Create response：`https://developers.openai.com/api/reference/resources/responses/methods/create`
- Streaming events：`https://developers.openai.com/api/reference/resources/responses/streaming-events`
- Migrate to Responses：`https://developers.openai.com/api/docs/guides/migrate-to-responses`

采用显式 `input` 消息、`input_text` / `input_image`、Bearer 认证、`stream: true`。参数映射为 `max_output_tokens`、`reasoning.effort`；官方 create 参数约束中 max_output_tokens 最小值为 16，程序在保存模型、本页覆盖和生成前进行检查。实际模型是否支持温度和推理强度仍由用户声明并通过测试确认。

本页记录的是本次实现采用的协议子集，不宣称实现完整 Responses API。

## 请求地址规则

- 空路径补 `/v1/responses` 或 `/v1/chat/completions`。
- `/proxy/v1` 等前缀保留；已有完整 `/responses` 或 `/chat/completions` 端点，按当前模型协议替换已知后缀，不重复拼接。
- 显式根端点 `/responses` 保持根路径，不强加 `/v1`。
- 供应商和模型编辑界面预览最终地址；生成确认再次显示实际协议与地址。
- 保留 HTTPS 要求、仅本机 HTTP、禁止 URL 内凭证/查询/片段、禁止自动跟随重定向。
- 更改供应商最终请求地址需重新填写密钥；模型协议覆盖仅改变同一 Base URL 的协议后缀。

## 状态与数据边界

- Responses 请求固定 `store: false`，不发送 previous_response_id、conversation、tools 或 background。
- 每次调整显式发送本次确认的系统提示词、基础经历、当前正文和修改要求；版本关联只在本机保存，不建立服务端会话链。
- `store: false` 是响应存储设置，不是第三方供应商绝不记录日志的承诺。
- 仅 `response.output_text.delta` 进入正文流预览；reasoning 等内容不进入正文或历史。
- 仅接受 `response.completed` 且 response.status / message.status 完整、无 error/incomplete_details、包含有效 assistant output_text 的结果。
- 将分片正文与最终 output 校验；不一致、片段缺失、重复序号、响应标识不一致均拒绝保存。
- `output_text.done`、Chat 的 `[DONE]` 和连接结束都不能替代 Responses 完成事件。
- incomplete、failed、error、拒绝、工具输出、无正文、无效结构、超时和取消均不生成正式版本；原正文和修改要求保留。
- 保留响应大小限制、总体超时、用户取消和错误脱敏，不显示供应商错误响应原文。
- 图片测试只使用程序内红色样本；用户附件尚未在 P05 开放。

## 用户验收步骤

1. 正常退出旧程序，完整解压 0.5.1 ZIP 后打开其中的 Career Assistant.exe。检查已有 Chat 模型、草稿和历史仍在。
2. 添加新的供应商，默认接口协议选择 **OpenAI Responses**，填写服务商的 Base URL、API Key；检查最终地址。
3. 添加模型，填写真实模型 ID 和显示名称；模型协议可继承，或显式选择 Responses。
4. 只勾选模型实际支持的参数；输出上限不能小于 16。先确认执行文本测试，若需要可另行确认图片样本测试。
5. 在设计简历页选择该模型，生成 V1；填写修改要求并确认调整，得到 V2。
6. 在本页记录检查协议快照，预览 V1 不改变 V2；恢复 V1 新建 V3，且不发 API 请求。
7. 关闭重开，检查当前正文与所有历史仍在。取消一次调整，确认原正文和修改要求不变。
8. 可另加 Chat 模型回归；切换协议后重新测试能力，不把旧协议测试记录当成当前结果。

正式包加固与数据边界详见 [P05 安全复核](p05-security-review.md)。
