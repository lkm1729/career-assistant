# P10/P11 · 0.10.0 实施与验收记录

日期：2026-09-16。基线为0.9.2；旧发行目录不修改。

## 范围与结论

按开发章程补齐 P10/P11 的本机实现，并为用户“简历PDF + 岗位链接”验收提前接入 P12 的公开网页基础链路。P10/P11 交付用户验收，不宣称真实供应商、所有招聘网站或整份章程已通过最终验收。

### P10 岗位匹配

- 四个工作区现在都能持有隔离的资料项；匹配页按简历、岗位、补充证据用途导入文件/图片并预览、勾选。PDF/DOCX/图片解析继续复用 P08 本机解析器和内置中英文 OCR。
- 匹配确认页展示供应商/模型/实际协议/地址/参数、岗位与简历文字、补充证据、系统提示词、附件/图像清单和降级警告。默认不发送图像；发送图像前检查实际所选模型视觉能力。
- 来源以 `material-id:pN` 定位到文件页；岗位证据只能来自岗位来源，经历证据只能来自简历/补充证据。空引用、虚构引用、重复要求ID、没有证据的“已体现/部分体现”不能入库。
- 硬性条件由要求项派生；硬性条件未完整体现时建议强制为待确认。证据覆盖率由有经历证据的“已体现/部分体现”项数除以提取的要求项数计算。它不证明模型提取了全部岗位要求，不是概率或ATS分数。
- 独立匹配记录保留输入、模型配置、来源文字和无图片二进制的资料快照；不会修改简历正文。单条SQLite INSERT具有原子性，不插入流式半成品。历史目前保留，不提供永久擦除入口；附件移除为逻辑移除，不等于安全擦除。
- 修正此前请求忙碌页误记为score、匹配按钮误依赖resume模型、准备阶段不检查草稿保存结果的问题。请求取消、配置变化、草稿变化、资料变化均不能保存过期结果。

### P11 求职信

- 同样支持本页简历PDF、岗位资料和补充证据文件/图片及独立文字。绝不自动读取设计简历或岗位匹配页。
- 发送清单、生成和继续调整均使用本页manifest。完成前检查附件与模型配置未改变；正文版本事务检查源简历和补充证据未改变。
- 复用既有独立版本、切换/回滚、回收站、草稿备份和正文/说明分离机制。切换/回滚不是新生成；只有模型生成/调整成功创建新版本。
- 重启保留源简历、补充文字、附件选择和正文历史。

### P12 本轮增量：主动读取网页

- 匹配页和求职信页均可按岗位/补充证据用途，每批最多5个链接依序读取。某个链接失败时停止该批；此前成功快照保留，不自动勾选，不覆盖旧资料。
- 两层确认：先确认联网访问网站并保存本页快照；再预览、手动勾选，最终确认发送给供应商。访问网站会暴露网络IP，不带简历、供应商Key、Cookie、登录状态或Referer。
- 只支持公开HTTPS/443及公共IPv4。URL验证拒绝凭证、危险协议/端口/内网等；DNS所有A记录验证后钉住选定IP建立TLS，使用原始域名验证证书；重定向每跳重新验证、最多3跳，仅自动跟随同源跳转。
- 请求20秒总时限、2 MiB响应/120000字符限额；取消DNS等待也会及时释放界面。纯静态文字抽取，不执行脚本、不下载子资源、不绕过登录/验证码；恶意未闭合HTML使用向前扫描，避免大正则反复回溯。
- 来源保留地址（不含查询参数）、时间、警告和原文快照。网页可能包含导航/广告、遗漏动态正文；必须预览核对。跨站跳转请复制浏览器最终公开地址重试。不能读出的站点可粘贴正文、导入PDF或截图。
- 完整P12仍待后续：更多招聘站点适配、标题/状态完善、专门的冲突确认交互和整体安全验收。当前靠资料预览、取消冲突项及发送前确认，不自动合并冲突职位。

## 用户验收顺序

1. 正常关闭旧版，完整解压新版ZIP并运行EXE；不要跨版本同时编辑同一数据库。
2. 在岗位匹配页配置/选择模型，导入简历PDF，展开预览后勾选。
3. 网页用途选目标岗位，粘贴链接并确认访问；展开文字快照核对岗位要求后勾选。不成功就粘贴正文/导入PDF或截图。
4. 默认文字模式先跑一次；有视觉能力再勾选图像。核对发送清单，确认发送并匹配。
5. 查看原文证据、硬性条件、警告、覆盖率与申请依据；取消/失败后旧记录仍在。
6. 求职信页需重新明确导入本页资料，生成、继续调整、切换旧版、回收/恢复后重启检查。不会自动复用匹配页资料。

进度口径：P10/P11本机实现已补齐，待用户验收；后续主线还有P12/P13/P14三阶段，计入待验收则五阶段未最终关闭。
