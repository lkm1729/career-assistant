日期：2026-09-19。基线：0.13.4。用户报告10轮真实测试仍有2–3次失败，提供新附件及消息中的单行响应。用户报告不是统计显著的失败率估计；本轮不据此承诺总体成功率。

## 实际证据与假设检验

- 新附件111行、5031字符。旧版parseScore稳定重现AI_SCORE_JSON / SEPARATOR_REQUIRED；失败位置在summary，而非已有的issues/suggestions。
- 单变量实验：仅转义summary中两个已有英文双引号，旧版解码通过。全文54个裸正文引号，另52个已由0.13.4兼容。
- 消息内响应另有单行issues/suggestions、example内引用短语及转义换行。虚构最小回归分别重现单行建议、summary、example三个遗漏点；全部先红后绿。
- 同一内容从多行改为单行会越过0.13.4独占一行的识别条件，说明剩余问题是兼容规则绑定排版、且遗漏两个说明字段，不是据此认定协议网络失败。

## 最小修复

1. 常规JSON语法优先：整个文档能按原语法解析时直接返回；只有语法失败才尝试明确启用的说明字段兼容，避免重新解释合法JSON。
2. 仅允许根summary、dimensions数组直接元素的example、issues/suggestions数组项。sourceId、quote、score、key、页面清单以及其他字段不放宽。
3. 不再依据行首/行尾猜边界；依据当前数组/对象上下文，在第一个可能的结构边界停止。只保留原本存在的成对正文引号，不补字段、引号、分隔符、容器或内容，不跨过分隔符寻找更方便的结尾。
4. 引号未配对、疑似新字段/容器/注释/缺分隔符等含糊情况继续拒绝；不猜测原始跨行坏字符串。合法的JSON换行转义正常保留。
5. 保持单说明值16000字符、32对内引号，文档700000字符、64层嵌套限制；重复字段保护、原型键保护及后续评分/证据/完整性校验不变。
6. 评分提示词覆盖四类说明字段的转义要求。成功兼容仍提示PROSE_QUOTES；不自动重试、不改变供应商协议/结构化输出配置，不更改正文历史或工作台。

这是限定语法兼容，不是通用修复器；不能保证所有未来模型畸形输出都能成功。
