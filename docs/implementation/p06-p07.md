# P06 + P07：两种原生协议并行接入

日期：2026-09-15
交付版本：0.7.0
状态：本机实现与自动化验收完成；交付正式 ZIP 测试包，真实供应商及完整正式包业务交互待用户验收。

## 接入方式

- P06：Gemini 原生 streamGenerateContent，使用 x-goog-api-key 请求头；不把密钥放到 URL。默认根地址补 /v1beta，保留用户代理前缀；模型 ID 进入经过检查的路径，程序添加 alt=sse。
- P07：Anthropic Messages，使用 x-api-key 和 anthropic-version；默认根地址补 /v1/messages，保留代理前缀。
- 两者均用 SSE 独立解析器，经既有 AiService 完成简历生成、调整和事务性版本保存，不复制一套业务存储。
- 模型可以继承供应商协议或显式覆盖；UI 显示实际协议、最终地址和有效参数。历史记录保持当时的协议快照。
- 供应商/模型协议变化使旧测试记录过期；若继承模型或页面覆盖含不兼容参数，先拒绝修改，不把不能执行的配置写入数据库。

## 参数与兼容范围

- Gemini 支持本批 temperature / maxOutputTokens；Anthropic 支持 temperature（0–1）/ max_tokens。
- Anthropic 请求要求输出上限，未覆盖时 4096；写入有效参数快照并在确认中展示，不冒充没有发送参数。
- 不启用通用 reasoningEffort 映射；不同模型的 thinking 配置后续独立设计，不静默忽略。
- 当前是 API Key 的原生文本/图片样本协议子集，不是 Vertex AI OAuth、工具调用、批处理或全部 API 功能。
- 通过中转服务使用 Gemini/Claude 模型时，应按服务实际协议配置；模型名称不决定传输协议。仅提供 OpenAI 兼容接口的代理继续使用 Chat Completions / Responses。
- Base URL 不接受查询参数；即使复制官方流式 URL，也应去掉 ?alt=sse，由程序补齐。禁止 URL 内 key、用户名、密码和片段。

## 安全与本地数据

维持 0.5.1 的 HTTPS、禁止重定向、主进程密钥加密使用、IPC 来源检查、正式包调试禁用和 ASAR 完整性验证。不添加遥测、自动同步、外部脚本执行或工具调用。

正文流与服务端思考内容分离；不完整、取消、工具输出、拒绝和异常结果不创建版本。恢复旧版本仍是本机复制，不请求服务商。应用无法承诺第三方供应商绝不留日志。
