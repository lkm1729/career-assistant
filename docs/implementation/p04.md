# P04：简历调整和非破坏性版本恢复

日期：2026-09-15
交付版本：0.4.1（0.4.0 的 P04 初步实现保留，补齐功能与验收）

## 已实现的用户行为

- **继续调整**：发送前展示供应商、模型、参数、系统提示词、基础经历、当前正文及本次修改要求；确认后才调用 Chat Completions。成功生成新的正式版本，并清空已消费的修改要求。
- **版本追溯**：历史显示生成 / 调整 / 恢复类型、父版本、恢复来源和当前版本标识。调整要求独立保存；旧版未记录的要求明确显示为未记录，不伪造。
- **独立预览**：查看历史正文、建议、说明和输入快照不会切换当前工作区。
- **非破坏性恢复**：恢复前需二次确认；仅在本机复制正文、建议和说明，追加新版本，不删除旧版，不调用 API，不回退模型配置、基础经历和系统提示词。
- **保留手改内容**：恢复前的手工正文、基础经历、系统提示词和待处理修改要求写入新版本输入快照；恢复不再悄悄丢失待处理要求。
- **当前草稿与正式版本区分**：手改正文解除正式版本关联，显示本地草稿，不再套用最新历史版本的建议。旧版建议仍可在记录中查看。
- **失败与取消**：不创建半成品版本，不改写原正文，不消耗修改要求。

## 安全与一致性

- 恢复前先等待前端写入队列排空，并读取已保存草稿作为确认快照。
- IPC 要求提供确认时的完整草稿；SQLite 事务内再次比较，确认后若内容发生改变则拒绝恢复。
- 恢复按钮防止重复并发操作；恢复期间锁定简历编辑，通信异常提示先检查历史，避免重复创建版本。
- 正式版本插入和草稿替换在同一个 SQLite 事务中执行，故障时一并回滚。
- 保留旧格式数据库兼容；缺失 currentVersionNumber 时按本地草稿处理。
- 本次开发未读取或改写真实用户数据库，未使用真实 API Key。测试使用独立目录和虚构密钥、本机模拟 HTTP 服务。

## 手动验收建议

1. 先正常关闭旧版，打开 0.4.1；确认原有供应商 / 模型与简历草稿仍在。
2. 生成 V1，输入一条修改要求并确认调整，得到 V2。
3. 预览 V1，关闭记录，确认当前仍为 V2。
4. 从 V1 恢复并确认，得到 V3；V1/V2 仍存在。
5. 手改正文并留下未发送的修改要求，再恢复 V2；查看新版本输入快照，确认手改内容和要求保留。
6. 关闭重开；当前正文、版本指示与所有记录一致。
7. 对一次调整执行取消，确认旧正文和修改要求不变。
