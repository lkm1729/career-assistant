# Career Assistant 产品规格

日期：2026-09-14
状态：产品基线已确认；P01 基础工作区、P02 单连接文字简历生成已实现，其余功能待实施。依据当前对话，后续明确修订优先于此前建议。

## 1. Problem Statement

用户可能已经拥有简历，只需要评分、判断某个岗位是否值得申请，或撰写求职信。产品应提供四个可直接使用的工具，而不是强制顺序流程；用户使用自己的 AI 服务连接处理资料。

## 2. Solution

Windows 桌面应用，包含设计简历、简历评分、岗位匹配度评估、撰写求职信四个独立标签页。全局仅管理供应商、模型和应用设置。简历正文和求职信均支持基于提示词调整与非破坏性版本恢复；两种评估保存独立评估记录。

### 确认的范围

- 四页各自拥有输入、系统提示词、模型选择、附件、运行状态及结果，不自动跨页读取资料。
- 四种协议：OpenAI Chat Completions、OpenAI Responses、Gemini、Anthropic Messages。此前“OpenAI Completion”按对话澄清理解为 Chat Completions，不包含旧式文本 Completions。
- 供应商与模型两级管理，支持单项和多选删除、连接测试、能力标记、高级参数。
- 设计简历与撰写求职信使用上、中、下纵向布局；二者均支持 V1、V2、V3 等版本及回滚。
- 简历以 Markdown 内容、排版美化建议和设计说明为主，不制作专业排版设计器。
- 简历评分包含真实视觉排版评价，四维卡片、百分制指标条与 Summary。
- 岗位匹配补充证据支持图片、文件、网页链接。
- 求职信支持 Markdown 与 Raw Text，额外要求在提示词内输入。
- 深色、浅色、跟随系统；iOS 风格桌面界面；英文和数字 Google Sans，中文 MiSans。

## 3. User Stories

1. 作为已有简历的用户，我想直接评估岗位匹配度，以便不先生成简历。
2. 作为明确申请目标的用户，我想直接撰写求职信，以便独立完成申请材料。
3. 作为用户，我想切换标签页后保留当前内容，以便稍后继续处理。
4. 作为用户，我想不同标签页的资料独立，以便不意外发送其他任务的材料。
5. 作为用户，我想添加多个供应商，以便使用自己的不同服务。
6. 作为用户，我想在每个供应商下添加多个模型 ID 和显示名称，以便识别并选择模型。
7. 作为用户，我想单项或批量删除模型和供应商，以便维护连接列表。
8. 作为用户，我想按协议自动补全请求地址并预览最终地址，以便排查连接错误。
9. 作为用户，我想分别测试连接、文本生成和图片能力，以便知道模型实际可以处理什么。
10. 作为用户，我想按“模型显示名称 / 供应商”选模型，以便避免同名模型混淆。
11. 作为用户，我想设置高级参数和能力标记，以便适配自定义服务。
12. 作为用户，我想修改每页的默认职业顾问系统提示词，并恢复默认，以便调整分析偏好。
13. 作为用户，我想一次添加多张图片和多个文件，以便提供完整资料。
14. 作为用户，我想检查资料识别结果与失败项，以便修正缺失输入。
15. 作为用户，我想查看本次发送的资料和目标供应商，以便决定是否发送敏感内容。
16. 作为用户，我想生成 Markdown 简历及独立的排版建议和设计说明，以便自行编辑和美化。
17. 作为用户，我想在正文下方输入修改要求，以便进一步调整而不受固定按钮限制。
18. 作为用户，我想查看简历旧版本并非破坏性恢复，以便安全比较不同表达。
19. 作为用户，我想对简历进行通用评分或目标岗位评分，以便获得相应的改进建议。
20. 作为用户，我想查看四维评分卡片与原文证据，以便理解评分理由。
21. 作为用户，我想让评分检查视觉版面，以便发现结构、密度和可读性问题。
22. 作为用户，我想知道哪些维度没有完成评价，以便不误信不完整分数。
23. 作为用户，我想获得建议而不是被引导到另一个工具，以便自行决定如何修改简历。
24. 作为用户，我想为岗位评估分别提交岗位资料、简历和补充证据，以便区分材料作用。
25. 作为用户，我想将图片、证书文件和作品集链接作为补充证据，以便体现完整经历。
26. 作为用户，我想查看岗位要求与材料证据的对应关系，以便判断优势和差距。
27. 作为用户，我想分别看到硬性条件与综合匹配度，以便不被总分掩盖关键缺口。
28. 作为用户，我想获得是否建议申请及理由，以便合理分配申请精力。
29. 作为用户，我想在求职信提示词中指定语言、语气和字数，以便无需填写复杂表单。
30. 作为用户，我想复制 Markdown 或纯文本求职信正文，以便在不同申请渠道使用。
31. 作为用户，我想调整和恢复求职信版本，以便保留不同写法。
32. 作为用户，我想取消运行并在失败时保留原结果，以便避免损失已完成内容。
33. 作为用户，我想关闭后再次查看各页的本地任务历史，以便延续工作。
34. 作为用户，我想切换深浅主题，以便适应阅读环境。
35. 作为用户，我想通过 Windows EXE 安装使用，以便不需要开发环境。

## 4. Implementation Decisions

### 4.1 应用和隔离边界

采用 Electron、React、TypeScript；本地数据库采用 SQLite，附件由桌面服务层管理，密钥采用操作系统支持的加密存储。具体依赖版本在实施时核验并固定。

- UI 通过受限 IPC 调用桌面服务，AI 请求、密钥使用、文件访问在服务侧完成。
- 求职任务所属标签页固定。读取、解析、运行、历史查询均按任务归属校验；不能只在 UI 隐藏其他页资料。
- 共享解析器或协议适配器，不共享任务数据。
- 供应商删除不删除正文、评估记录或附件；相关页面标记模型不可用，要求重选。
- 模型配置变化不修改过去结果的模型名称快照。

### 4.2 供应商、模型、参数

供应商配置：稳定标识、名称、Base URL、密钥引用、默认协议。
模型配置：稳定标识、供应商归属、模型 ID、显示名称、能力标记、默认高级参数。

实现默认值：模型可覆盖供应商默认协议；标签页可临时覆盖模型参数。参数优先级为本次运行、标签页、模型默认；未支持参数不发送。

地址构造需按协议处理版本段、路径前缀及已填写完整端点，不做简单字符串重复拼接。高级设置允许完整请求地址覆盖，并展示最终地址；详细规则以协议契约测试验证。

四协议使用独立请求和流事件适配器，输出统一的正文增量、完成、取消和失败事件。协议选择不等于已验证图片、文件、结构化输出能力；能力标记允许人工修正，测试结果记录验证时间及范围。

连接测试明确区分地址可达、认证、文本生成和图片验证。可能产生费用或发送样本的测试先说明并由用户触发。密钥不出现在日志、普通配置导出或结果快照中。

### 4.3 共用输入处理

- 初版目标格式：PDF、DOCX、TXT、Markdown；PNG、JPEG、WebP；允许多个资料项。
- 网页功能用于岗位匹配和求职信中的岗位资料及补充证据；不擅自给其他页扩展跨页资料入口。
- 流程：导入校验 → 抽取文字/渲染/OCR → 预览状态及错误 → 用户确认资料 → 适配模型 → 运行。
- 资料保留用途、来源、读取时间、解析状态和页码等证据定位信息。
- PDF 同时提供文字和页面图像；DOCX 尝试渲染并提示字体替换风险；扫描材料提供 OCR 和原页面。
- OCR、渲染方案、资源限制、页数及上下文预算属于实施时确定的工程参数，不隐瞒截断或页面遗漏。
- 优先本机抽取、渲染和 OCR；任何额外云端解析服务必须另行明确告知和授权，不暗中上传。
- 网页限制为公开 HTTP/HTTPS，阻止本机、内网、特殊目标及危险重定向，不绕过登录或验证码；失败时支持粘贴正文或截图。
- 外部材料视为数据，不作为系统指令。应用不运行网页或模型输出的脚本。

### 4.4 系统提示词

四页各有专业 Career Advisor 默认模板，支持查看、编辑、另存、恢复默认。公共原则包括事实保真、证据引用、区分推断与未知、避免无关个人属性评价、拒绝虚构成果。

任务模板分别约束简历组织、固定量表评分、岗位证据对应和求职信定制表达。内容、排版建议、设计说明分字段保存；设计说明是简明依据，不要求模型内部推理。

用户可自定义提示词，但不能绕过程序端数据格式校验、文件访问控制或密钥保护。模板全文在对应功能切片实施，不将一句角色描述视为完成。

### 4.5 设计简历

上侧输入资料和模型设置；中间正文、Markdown 预览/源码、排版美化建议和设计说明；下侧自由调整提示词及版本列表。输出以 Markdown 为主，支持复制、保存 Markdown；专业版面编辑和 PDF/DOCX 导出不是初版必需项。

每次调整明确使用当前工作版本及用户指令。实现默认值：允许手动编辑正文，编辑作为草稿，明确保存后形成新版本，避免静默改写历史。

### 4.6 正文版本：适用于简历和求职信

- 编号在单个求职任务内递增；不同页、不同任务各自从 V1 开始。
- 首次成功结果创建 V1；成功调整创建后续版本并记录父版本。
- 预览旧版本不改变当前工作版本；恢复操作复制旧正文及关联说明，创建新编号并记录恢复来源，不调用 AI。
- 从旧版本继续调整创建新版本，保留原分支所有版本。
- 保存正文、说明、时间、修改指令、来源版本和模型快照；恢复版本区分原生成模型与“本次未调用 AI”。
- Markdown/Raw Text 展示切换不新建版本。纯文本是同一正文的确定性展示/复制方式，而非重新调用模型。
- 失败或取消保留旧版本。流式未完成内容不自动成为正式版本。
- 实现默认值：每任务同时最多一个写入型运行，重复完成事件不重复创建版本；取消后的迟到事件不得覆盖结果。
- 正文版本不等同于整个任务或所有附件的时间旅行。运行保留输入资料引用和提示词快照；附件不可用时明确提示，不承诺能够原样重跑。

### 4.7 简历评分

可提供目标岗位倾向，留空则通用模式。显示总分指标条、四张横向可展开卡片和 Summary；窄窗口卡片可换行。无“送到设计简历”按钮。

| 维度 | 权重 | 证据要求 |
| --- | --- | --- |
| 内容完整性与成果证据 | 30% | 经历、成果、支持材料 |
| 岗位或职业方向相关性 | 30% | 有目标则对应岗位；无目标则评价定位与聚焦 |
| 结构、视觉排版与可读性 | 20% | 页面图像及可辨识结构 |
| 表达准确性与专业性 | 20% | 原文措辞、语言与一致性 |

每项子分为 0–100，由程序按权重算总分并统一取整，保存量表版本。分项展示证据、问题、建议、必要时提供修改示例。

无法取得可评价图像或模型不支持视觉时，标注视觉维度未评价，展示部分评价但不生成完整总分；不得当零分或悄悄重分配权重。多页未全部评价时显示覆盖范围。评分不是招聘方真实 ATS 分数或录用概率。

### 4.8 岗位匹配度评估

输入分为岗位资料、用户简历、补充证据。岗位资料支持文字、图片、链接和文件；简历支持图片和文件；补充证据支持图片、文件和链接。

输出：百分制匹配条、岗位要求—材料证据对照、已体现/部分体现/未找到证据/待确认状态、硬性条件、Summary 和申请建议及理由。未找到证据不等同于没有能力；硬性条件不能被综合分掩盖。多个链接内容冲突时提示确认，不静默拼成单一岗位。

实现默认值：匹配量表单独版本化，不复用简历质量量表；具体维度、权重、信息不足时的计分规则在该切片开始时提出并确定。不得在规则未确定前把模型随意给分作为最终产品逻辑。

### 4.9 撰写求职信

上侧输入，下侧调整与版本，中间正文工作区。岗位图片/链接、简历图片/文件和补充资料按用途分组。语言、字数、语气等额外要求由用户提示词指定，不强迫填写复杂表单。

支持 Markdown 阅读预览、源码、Raw Text 和只复制正文；撰写说明独立。依据真实材料回应岗位需求，不虚构业绩、关系或公司事实。版本采用 4.6 的统一规则。

### 4.10 历史、隐私与外观

各页本地保存独立任务历史。两种评估保存输入关联、模型及量表快照、结果、时间；重新评估产生新记录，不执行正文回滚。

应用说明本地保存不等于离线推理，运行前展示目标供应商和所选材料。密钥加密不代表简历库已加密，不作过度安全承诺。数据清理需确认影响范围；备份默认排除密钥。具体备份入口可后续安排。

iOS 风格表现为圆角、分组卡片、轻量层次，不照搬手机窄屏。设计简历和求职信为纵向三区。界面支持浅色、深色、跟随系统；保留焦点、键盘可用性、对比度、状态文字和减少动画偏好。

英文数字使用 Google Sans，中文使用 MiSans；打包前核验取得的字体文件及许可，配置后备字体，不在启动时依赖在线字体。

## 5. Testing Decisions（建议测试边界，未实施）

当前为空项目，没有现有测试先例。优先从可观察行为验收，而非绑定内部组件结构。

- 最高层：桌面用户流程覆盖任意页直达、输入隔离、取消、重启恢复和两个页面的版本恢复。
- 服务边界：可控的协议响应与时间，验证错误、流中断、迟到完成、重复完成和数据库写入的外部结果。
- 协议契约：四协议分别覆盖路径、认证、不支持参数、流事件与能力不足；默认使用本地模拟服务，不自动消耗真实 API 配额。
- 资料样本：文字 PDF、扫描 PDF、DOCX、截图、损坏文件、链接失败与恶意外部指令；检查页码和证据对应。
- 安全：任务越权访问、IPC 入参、恶意 Markdown、网页内网及重定向、密钥日志泄露。
- 视觉评分：图片缺失、模型无视觉能力、部分页面失败、子分越界和量表版本变化。
- Windows 交付：没有开发环境的目标环境安装与启动、字体、文档渲染依赖、卸载与升级保留用户资料。安装测试与真实 API 冒烟在授权范围内进行。

## 6. Out of Scope

全局求职资料库；跨页自动传递资料；强制顺序流程；专业画布和 Canva 式编辑；必须的 PDF/DOCX 排版导出；账号系统；云同步；自动投递；招聘网站登录绕过；插件市场；自动选择收费服务；未经授权的 Git 或远端写入。
