# Career Assistant

Windows 本地优先的 AI 求职助手：在四个相互独立的工作台中处理简历、岗位匹配、评分和求职信，支持 PDF、DOCX、图片、文字及经确认的公开网页资料。

## 当前版本：1.0.0（2026-09-19）

1.0.0 是 Career Assistant 的首个正式开源版本。0.13.7 是正式版前的最终测试版本；本次正式版保留其稳定功能与安全边界，并将版本号、Windows 安装包、免安装 ZIP、第三方许可证清单和发布校验统一到 1.0.0。

> **发布状态说明：** 本地类型检查、格式检查和 828 项单元/服务测试已通过。Windows 安装包当前未签名；真实供应商、独立干净机器和签名验证仍需分别评估，不能由本地模拟测试替代。

## 功能概览

- **四个独立工作台**：简历/求职材料生成、岗位匹配、岗位评分和求职信；资料默认不跨页共享。
- **本地资料处理**：PDF、DOCX、图片和文字导入；内置 PDF/DOCX/OCR 解析资源，支持预览、用途标记和发送前确认。
- **多供应商协议**：Chat Completions、OpenAI Responses、Gemini 原生协议和 Anthropic Messages 原生协议；按实际接口协议路由，不按模型名称猜测。
- **证据约束**：岗位匹配和评分结果必须引用已验证来源；程序计算覆盖率和硬性条件，不把模型返回的派生分数直接当作事实。
- **本地历史与恢复**：生成结果、版本、回滚、清空和撤销保持页面独立，失败或过期请求不会覆盖新的本地状态。
- **安全边界**：不自动上传、不做云同步、不加入遥测；只有在用户明确确认后，才读取公开网页或将选定资料发送给供应商。

## 安装与使用

从 GitHub Releases 下载 Windows x64 安装程序或免安装 ZIP：

- `Career-Assistant-1.0.0-Setup-x64.exe`
- `Career-Assistant-1.0.0-win-x64.zip`
- `SHA256SUMS.txt`

安装前请关闭正在运行的 Career Assistant。应用数据位于 `%APPDATA%\\Career Assistant`，更新和正常卸载不会删除已有数据，但卸载不是安全擦除；重要资料请自行备份。

远程 AI 请求需要用户配置供应商端点、模型和密钥。密钥由应用本地加密保存；项目不会把密钥写入日志、README、测试报告或诊断信息。公开网页读取需要单独确认，读取后的资料还需要用户预览、选择并再次确认是否发送。

## 隐私与数据边界

Career Assistant 以本地优先为设计原则：

- 运行时资料、草稿、历史、供应商配置和本地加密密钥保存在本机。
- 不包含自动遥测、云同步或后台上传。
- 未选择的资料不会被发送；页面之间不会自动共享资料或提示词副本。
- 公开网页导入需要明确的联网确认，并限制为公开 HTTPS 内容和受约束的文本快照。
- 第三方供应商的服务器日志、代理日志、计费记录和数据保留策略不由本项目控制，请按供应商政策单独评估。

## 0.12.1 / O1 资料管理优化（历史基线，用户已实测验收）

- **资料保护**：从当前页软移除，不删除原文件或历史快照，不作数据库安全擦除；各标签页继续隔离。

### 用简历 PDF 和岗位链接测试匹配

1. 正常关闭旧版，完整解压新版，在“岗位匹配”页选择本页模型（不需要给设计简历页选模型）。
2. 点击“多选导入文件 / 图片”，选择PDF和其他材料；在待导入清单逐项设置用途，点击“确认用途并导入”。等待本机解析，展开逐页预览并勾选“发送资料”。
3. 在网页区域选择“目标岗位”，粘贴完整 HTTPS 链接（每行一个）。点击“读取网页前确认”，逐条核对网站和用途后确认访问。
4. 网页只保存到本页，默认未勾选。预览正文是否确实包含岗位要求，而不是登录提示或导航；核对后手动勾选。
5. 多份岗位有冲突时只选本次目标职位，补充材料选“补充证据”。可在文字框补充遗漏或纠正 OCR。
6. 默认只发抽取文字；模型支持视觉且确有需要时才勾选“本次发送页面图像”。没有可引用文字的图片事实只能待确认，不能伪造原文引用。
7. 点击“评估匹配度”，核对供应商、协议、模型、参数、文本和附件清单，再“确认发送并匹配”。这一步会联网调用所选模型。
8. 查看逐项证据、硬性条件、覆盖率、申请依据和警告。历史是独立匹配快照，不覆盖简历正文。

网页限制：只接受公开 HTTPS/443 和公共 IPv4，最多3次同站跳转、20秒、2 MiB响应/120000字符。不带 Cookies、账号登录或 API Key；跨站跳转需复制浏览器最终公开地址后重试。动态、登录、验证码网站可能无法读出岗位，改用粘贴正文、PDF或截图。未实现网页脚本执行、登录绕过、自动更新或跨页同步。

### 如何生成简历或求职信

1. 打开“应用设置”，填写供应商名称、Base URL、API Key、模型 ID 和显示名称。
2. 保存连接。保存只写入本机，不发请求；密钥保存后不回填明文，留空表示保留原密钥。包括修改请求地址时也可以留空保留。请确认新地址可信，下一次发送将使用新地址和原 Key。
3. 可先测试供应商连通性（GET 模型列表，无需先添加模型），再添加模型并点击“测试模型连通性”或图片探针。模型编辑页也可“保存并测试模型连通性”，保存后仍须确认发送。每次测试独立确认，不发送求职资料；列表探针失败并不必然表示生成不可用。
4. 回到“设计简历”或“撰写求职信”，为该页选择模型并粘贴真实经历、岗位资料和要求。两页均可导入本机文件和图片；求职信可读取本页岗位/补充证据网页，不读取设计简历页资料。
5. 点击“生成简历”或“生成求职信”，检查供应商、最终地址、提示词与当前正文，再确认发送。
6. 等待流式响应完成。正文、排版建议和设计说明分别保存，创建 V1；再次成功生成创建 V2、V3，不覆盖旧版本。
7. 使用“切换工作版本”下拉框，或在本页记录选择“切换到 Vn 并编辑”。工作区显示原编号并可编辑，不新增版本。“回滚”可恢复该版本原始正文；手动修改不会改写历史。

### P08 文件资料与 P09 评分使用

1. 在“设计简历”或“简历评分”页选择用途并多选导入；预览文字、页面图像、OCR 置信度和失败/遗漏提示。导入不上传。
2. 勾选本次需要发送的资料，按需选择发送图像。视觉能力未知时先做模型图片探针，或取消图像改用文字。
3. 评分页可粘贴简历正文；目标留空为通用模式。点击开始评分并核对确认清单。
4. 没有原始简历图像、只提供 DOCX 近似预览、页面不完整或有冲突时，不显示完整总分。四维固定权重为 30/30/20/20。
5. 每次成功评分形成独立历史，不更改简历正文版本。移除附件是逻辑移除，不是安全擦除。

限额：每文件 12 MiB、每页 16 项、每文件最多解析 8 页；发送最多 8 张图、12 MiB 图像、120,000 字符。本机资料副本总上限 512 MiB（含已移除副本）。OCR 内置英/简体中文，不依赖 Office；DOCX 预览存在字体和分页差异。

### 版本回滚、批量删除与撤销

1. 成功生成/调整得到 V1、V2、V3 后，切回 V1 仍显示 V1，不创建 V4；只有再次成功生成/调整才创建 V4。
2. 手动编辑后显示“编辑稿 · 基于 V1”；点击回滚会恢复 V1 的原始正文，当前输入资料和系统提示词保持不变。
3. 每次实际切换/回滚前保存完整草稿，可从本页记录的“切换前草稿”查看并确认恢复，避免丢失手工修改。
4. 在本页记录勾选多个旧版本，确认移入回收站；当前工作版本不允许删除。回收站支持多选恢复，原编号不重排。
5. 回收站是可撤销的列表清理，不是磁盘永久擦除。历史、回收站和备份按简历/求职信隔离，关闭重开继续保留。

### 错误诊断

供应商探针、模型探针和生成失败均展示红色错误码、可能原因和解决办法。HTTP 401/403/404/429/5xx 等保留状态码；网络、超时、流格式、配置变化等使用应用错误码。可能原因不冒充服务商的已确认原因，也不会显示服务商原始错误响应中的敏感文字。

### P05：使用 Responses

在供应商“默认接口协议”中选择 **OpenAI Responses**，模型统一继承供应商协议；保存后在简历页选择该模型。可以填写公共 Base URL 或完整 `/responses` 端点，先检查最终地址，再确认文本测试与生成。参数依模型声明启用：输出上限发送为 `max_output_tokens`（至少 16），推理强度发送为 `reasoning.effort`。Responses 使用 `store: false`、本机版本链，不启用服务端会话或工具；不代表第三方服务完全不留日志。详见 [P05 实施与验收](docs/implementation/p05.md)。

### P06 / P07：Gemini 与 Anthropic 原生协议

设置供应商默认协议或模型显式协议，检查最终请求地址再确认测试。Gemini 默认根路径补 `/v1beta/models/<模型ID>:streamGenerateContent?alt=sse`，API Key 在 `x-goog-api-key` 请求头；Anthropic 默认 `/v1/messages`，用 `x-api-key` 与固定 API 版本请求头。代理前缀保留，不携带 URL 密钥。

Anthropic 必须发送 `max_tokens`，未覆盖时为 4096，UI 会展示这一实际值；温度范围 0–1。Gemini 参数映射 `generationConfig.temperature/maxOutputTokens`。本批不将 OpenAI reasoningEffort 静默套到原生 thinking 参数，不启用工具、后台或远程会话链。

两者支持既有简历生成、继续调整、取消、版本保存/恢复和单独文本/图片样本测试；本版已在设计简历与评分页接入文件/图片导入。详见 [合并实施与验收](docs/implementation/p06-p07.md) 和 [开发进度](docs/progress.md)。

### 范围与限制

- 支持多供应商、多模型、单项/批量删除、页面独立选择及参数覆盖；删除配置不删除草稿和历史。文本、图片测试分别确认并保存测试记录。
- 支持 OpenAI Chat Completions、OpenAI Responses、Gemini 原生 streamGenerateContent 和 Anthropic Messages，以及匹配协议的兼容服务。不同协议分别处理路径、认证与流事件；模型名称不决定传输协议。
- 模型应支持文本 SSE 流和按提示输出结构化结果。缺失字段、模型拒绝、达到输出限制或流中断不会创建正式版本；需要用户重试或换模型，不自动重试收费请求。
- 为兼容不同模型，不发送未确认支持的温度或输出长度参数。总请求等待上限 120 秒，模型测试上限 30 秒、供应商列表探针上限 15 秒，响应大小有上限。
- Base URL 无路径时按协议补 `/v1/chat/completions` 或 `/v1/responses`；代理路径保留，已有完整端点按协议转换已知后缀。界面预览实际 URL；特殊服务需自行填写正确版本前缀。
- 远程连接要求 HTTPS；HTTP 仅允许本机地址。不接受地址内账号、密码、查询或片段，不跟随重定向，避免把密钥转发到其他目标。
- 普通生成发送已确认的基础经历、系统提示词和当前正文；“继续调整”另外发送本次修改要求。两者均附加输出格式约束，不发送其他页数据；简历和求职信均可发送已确认的本页附件，网页只使用你主动读取并勾选的文字快照。
- 简历/求职信生成期间锁定对应页编辑；其他页仍可编辑。取消或失败保留旧内容。完成时正文与版本在同一数据库事务内写入。
- 当前每页仍是一个工作任务；多任务管理尚未实现。正式版本与当前可编辑草稿分离，手动编辑不改写已保存版本。
- 四页均支持本页附件；岗位匹配 AI 已接通，P12 网页支持公开 HTTPS 静态快照与本地替代输入；P12/P13 已纳入验收基线，P14 本机交付收尾已完成，独立环境与许可事项见当前实施记录；不显示假评分或假进度。
- Google Sans 原文件已随包离线内置并附许可通知；MiSans 不重分发，使用本机已安装字体或 Windows 中文后备。第三方许可复核的未关闭项见 P14 实施记录。

### 0.11.0 使用变化

- 批量网页读取单次最多5个链接；成功项独立保存，失败项可手动修正链接后重新确认，或展开“网页读取失败？本地粘贴补充 / 截图说明”。补充文字保存后仍需勾选。
- 多份岗位附件，或岗位附件加文字输入，会显示同一目标岗位核对。即使求职信文字只是额外要求，也需确认它没有夹带另一岗位；有冲突请返回修改。每次发送重新确认。
- 在各页“系统提示词”内填写副本名称后另存，可从本页下拉列表选择并确认加载。每页最多20份，同名不覆盖；副本不会跨页出现或自动发送。
- 新增提示词副本与正文同样保存在本机普通 SQLite 中，不是整库加密。本版不提供永久擦除；移除资料仍保留本地副本与历史快照，界面会提示影响范围。

## 本地优先

应用没有自建云同步、遥测或自动上传。离线可编辑、保存、查看和恢复本机版本；远程 AI 只有在用户确认生成、调整或能力测试后才发送对应资料。应用不附带本地模型。供应商可能保留请求日志，不能把本机保存理解为 API 请求不离机。

0.7.0 延续 0.5.1 的 ZIP 便携目录，避免自解压启动器和不必要的提权辅助程序；正式包禁用开发服务器覆盖、调试入口、RunAsNode 和 Node 环境选项，启用 ASAR 完整性验证。详见 [安全边界复核](docs/implementation/p05-security-review.md)。不保证消除所有安全警报，不绕过系统安全提示。

项目源码可本地审查；尚无顶层 LICENSE，公开开源发行前仍需作者选择许可。此外，第三方清单的 reviewRequired 和原生组件传递许可链仍须关闭，不把不同版本的上游许可当成已核验的完整权利链。

## 数据与安全

Windows 本机密钥使用 Electron safeStorage 加密；明文仅在输入和发起请求时短暂使用，不写入普通日志或版本元数据。数据库中的正文、经历和历史仍未加密，不应把“密钥加密”理解为整库加密。

不要把 API Key 粘贴到提示词、正文或网页地址中。应用显示网络错误时不展示服务商响应原文，以避免错误响应泄露凭证。密钥加密失败时拒绝保存，不回退为明文。

删除连接需确认，只删除该连接及其加密密钥，不删除草稿或历史。密钥无法用撤销找回，需要重新填写。跨电脑复制数据库后，原机加密密钥可能无法解密，需要重新配置。

Markdown 不执行原始 HTML、不加载远程图片、不自动打开链接。导出先写入同目录临时文件，成功后替换用户选定目标。正常关闭窗口会等待草稿写入；生成仍在进行时会提示确认，放弃退出则取消当前请求。
